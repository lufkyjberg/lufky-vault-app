# Security policy

Vault уменьшает риск утечки секретов из WebView, но не является защитной границей от
скомпрометированной операционной системы, Administrator/root, кейлоггера или дампа памяти.

## Что защищается

- master password после unlock хранится в Rust state в `Zeroizing<String>`;
- обычное копирование пароля не возвращает его frontend-коду;
- при lock Rust session удаляется, frontend state очищается, clipboard очищается;
- release CSP запрещает внешние scripts, styles, frames и network connections;
- перед изменением KDBX создаётся зашифрованный backup;
- новый KDBX пишется во временный файл, синхронизируется, повторно открывается и только
  затем атомарно заменяет исходный файл.

## Известные ограничения

- KDBX4 writer библиотеки `keepass` экспериментальный;
- показанный пароль и новый пароль редактора кратковременно существуют в памяти WebView;
- библиотечная структура расшифрованной базы не гарантирует zeroization каждого поля;
- Windows screen-capture protection не является абсолютной защитой;
- Linux desktop-lock detection и screen-capture protection пока не реализованы;
- приложение пока не проходило независимый security audit или fuzzing.

## Безопасное использование

- сохраняй независимые резервные копии базы;
- сначала проверяй новые версии на копии KDBX и открывай результат в KeePassXC;
- не используй Vault на заражённой или недоверенной системе;
- включи BitLocker, LUKS или другое полное шифрование диска;
- устанавливай release только из доверенного исходного кода или подписанного артефакта.

Не прикладывай реальные базы, пароли, notes или clipboard contents к публичному issue.
